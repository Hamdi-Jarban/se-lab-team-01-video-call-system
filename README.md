## 1. نظرة عامة

`VideoCallSystem` هو تطبيق سطح مكتب لنظام Windows يوفر وظائف اتصال صوتي ومرئي مباشر من خلال بنية العميل والخادم.

يتيح النظام للمستخدمين تسجيل الدخول، ومتابعة المستخدمين المتصلين، وإرسال واستقبال طلبات المكالمات، وإجراء مكالمات صوتية ومرئية، وإدارة بعض حالات الغرف والجلسات.

يفصل النظام بين رسائل التحكم ونقل الوسائط كما يلي:

- **TCP:** رسائل التحكم، والمصادقة، وإدارة الجلسات، وتحديث الحضور، وإشارات المكالمات، وعمليات الغرف.
- **UDP:** نقل الصوت والفيديو في الوقت الحقيقي.
- **HTTP:** واجهة قراءة فقط لمراقبة حالة الخادم والاتصالات.

> **نطاق المشروع:** هذا المستودع مخصص للتطبيق الأكاديمي والتعليمي، ولا يُنصح باستخدامه في بيئة إنتاجية قبل إضافة متطلبات الأمان والاعتمادية والإدارة التشغيلية اللازمة.

## 2. الوظائف الأساسية

| الوظيفة | الوصف |
|---|---|
| المصادقة | تسجيل دخول مخصص للتطوير باستخدام اسم المستخدم وكلمة المرور. |
| الحضور | عرض قائمة المستخدمين المتصلين في الوقت الحقيقي. |
| إشارات المكالمات | إرسال وقبول ورفض وإنهاء طلبات المكالمات. |
| الصوت والفيديو | التقاط ونقل الوسائط في الوقت الحقيقي عبر UDP. |
| معالجة الصوت | معالجة عينات PCM مع مكوّن لإلغاء الصدى الصوتي. |
| التحكم بالوسائط | كتم وتشغيل الميكروفون وإيقاف وتشغيل الكاميرا. |
| الغرف | دعم عمليات الغرف الجماعية والدعوات ضمن مكونات العميل والخادم. |
| واجهة المراقبة | نقاط HTTP للقراءة فقط لمتابعة حالة الخادم. |
| واجهة العميل | واجهة سطح مكتب WPF مبنية باستخدام نمط MVVM. |

## 3. البنية المعمارية

```text
                         +---------------------------+
                         |          الخادم           |
                         |---------------------------|
                         | تحكم وإشارات عبر TCP     |
                         | ترحيل وسائط عبر UDP      |
                         | المصادقة                  |
                         | الحضور والغرف            |
                         | واجهة HTTP للقراءة فقط   |
                         +-------------+-------------+
                                       |
                    +------------------+------------------+
                    |                                     |
             +------+-------+                       +-----+------+
             | العميل الأول |                       | العميل الثاني|
             |--------------|                       |-------------|
             | WPF / MVVM   |<==== تحكم TCP ======>| WPF / MVVM |
             | كاميرا/ميكروفون|<==== وسائط UDP ====>| كاميرا/ميكروفون|
             +--------------+                       +------------+
```

### قنوات الاتصال

| البروتوكول | المنفذ | الاستخدام |
|---|---:|---|
| TCP | `5000` | التحكم والمصادقة والإشارات وعمليات الحضور والغرف. |
| UDP | `5001` | نقل الصوت والفيديو. |
| HTTP | `8080` | واجهة مراقبة الخادم على `localhost`. |

توجد إعدادات TCP وUDP في الملف:

```text
VideoCall.Shared/Networking/NetworkConfig.cs
```

أما منفذ واجهة HTTP فيُعرّف داخل:

```text
VideoCall.Server/Program.cs
```

- نظام التشغيل Windows 10 أو Windows 11.

## 9. تشغيل النظام

### 9.1 تشغيل الخادم

افتح نافذة PowerShell الأولى في جذر المشروع ونفّذ:

```powershell
dotnet run --project .\VideoCall.Server\VideoCall.Server.csproj
```

اترك نافذة الخادم مفتوحة أثناء اختبار العميل.

يستمع الخادم إلى منافذ TCP وUDP المعرفة في `NetworkConfig.cs`، ويشغل واجهة HTTP للقراءة فقط على المنفذ `8080`.

### 9.2 تشغيل العميل

افتح نافذة PowerShell ثانية في جذر المشروع ونفّذ:

```powershell
dotnet run --project .\VideoCall.Client\VideoCall.Client.csproj
```

عند ظهور نافذة تسجيل الدخول:

- استخدم `127.0.0.1` إذا كان الخادم يعمل على الجهاز نفسه.
- استخدم عنوان IPv4 لجهاز الخادم إذا كان الخادم يعمل على جهاز آخر.
- استخدم اسم مستخدم فريداً.
- استخدم بيانات اعتماد التطوير المعرفة في مصدر الخادم.

> لا تُنشر كلمات المرور التجريبية في مستودع عام. يجب استخدام مخزن آمن للبيانات وHash لكلمات المرور قبل استخدام النظام في الإنتاج.

### 9.3 اختبار عميلين

1. شغّل الخادم مرة واحدة.
2. شغّل العميل الأول وسجّل الدخول باسم مستخدم فريد.
3. شغّل العميل الثاني وسجّل الدخول باسم مستخدم مختلف.
4. أرسل طلب مكالمة من أحد العميلين.
5. اقبل أو ارفض الطلب من العميل الآخر.
6. اختبر الميكروفون والكاميرا والكتم وإنهاء المكالمة.

يمكن تشغيل عدة نسخ من العميل على الجهاز نفسه للاختبار المحلي، بشرط استخدام اسم مستخدم مختلف لكل جلسة.

## 10. واجهة مراقبة الخادم

يوفر الخادم واجهة HTTP للقراءة فقط على:

```text
http://localhost:8080/
```

تُستخدم الواجهة لمراقبة حالة الخادم والاتصالات، ولا تُستخدم كقناة تسجيل الدخول الخاصة بالعميل؛ إذ تتم مصادقة العميل عبر بروتوكول TCP.

> قبل استخدام الواجهة في بيئة إنتاجية، يجب إضافة المصادقة والتفويض وHTTPS وإدارة الإعدادات وضوابط الوصول التشغيلية.

## 11. إعداد جدار الحماية والشبكة المحلية

عند اختبار النظام على أكثر من جهاز، اسمح بالمنافذ التالية على جهاز الخادم عند الحاجة:

| البروتوكول | المنفذ | الاتجاه | الاستخدام |
|---|---:|---|---|
| TCP | `5000` | وارد إلى الخادم | التحكم والإشارات. |
| UDP | `5001` | وارد إلى الخادم | نقل الوسائط. |
| HTTP | `8080` | مراقبة محلية | واجهة المراقبة للقراءة فقط. |

تعتمد قواعد جدار الحماية الفعلية على بيئة التشغيل. يوصى بقصر الوصول على الشبكة المحلية وعدم تعريض خدمات التطوير مباشرة للإنترنت العام.

## 12. حل المشاكل الشائعة

### ظهور رسالة `dotnet is not recognized`

ثبّت [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)، ثم أعد فتح PowerShell وتحقق من الإصدار:

```powershell
dotnet --version
```

### تعذر اتصال العميل بالخادم

تحقق من التالي:

- الخادم يعمل قبل تشغيل العميل.
- عنوان الخادم صحيح.
- العميل والخادم يستطيعان الوصول إلى بعضهما عبر الشبكة.
- المنفذان `5000` و`5001` غير محجوبين.
- استخدام `127.0.0.1` فقط عند تشغيل الطرفين على الجهاز نفسه.

### ظهور خطأ في ترميز XAML أو XML

احفظ ملفات `XAML` و`C#` بترميز UTF-8، ثم نفّذ:

```powershell
dotnet clean
dotnet restore
dotnet build
```

### عدم توفر الكاميرا أو الميكروفون

تحقق من:

- منح Windows صلاحية استخدام الكاميرا والميكروفون.
- عدم استخدام الجهاز من تطبيق آخر بشكل حصري.
- توصيل الأجهزة قبل تشغيل العميل.
- اختيار أجهزة الإدخال والإخراج الصحيحة في Windows.

### رفض تسجيل الدخول

تحقق من:

- صحة بيانات اعتماد التطوير.
- عدم استخدام اسم المستخدم في جلسة أخرى.
- اتصال العميل بالخادم المقصود.
- سجل الخادم لمعرفة سبب رفض الطلب.
